## 使用说明

- 讨论顺序以用户真实使用拾忆的先后顺序为准。
- 节点状态使用：`下一步`、`待讨论`、`讨论中`、`已确定`、`待验证`。
- `下一步` 是当前即将讨论的节点；进入讨论后改为 `讨论中`。
- 暂不创建空白节点文档。每个节点讨论完成后再创建对应 Markdown 文件，并将下表中的文件名改成相对链接。
- 每完成一个节点，先保存节点文档，再将最终决策回写主规划书。
- 被替代的方案保留在节点文档的决策记录中，不继续保留在主规划正文。
- 每个节点都必须检查原子化单元、渐进验证、多路径适用性和动态降级行为；不适用时明确记录原因。

## 字段说明模板

每个输入和输出字段必须记录：

| 项目 | 说明 |
|---|---|
| 字段名 | API 和数据库使用的稳定名称 |
| 数据类型 | 字符串、数值、布尔、枚举、对象、数组或时间 |
| 是否必填 | 必填或可选 |
| 默认值 | 未输入时的确定行为 |
| 校验规则 | 长度、范围、格式、枚举和跨字段约束 |
| 来源 | 用户输入、系统检测、文件元数据或模型生成 |
| 展示位置 | 页面、弹窗、卡片、状态栏或仅后台使用 |
| 是否持久化 | 不保存、会话保存或长期保存 |
| 敏感级别 | 公开、本地一般、本地敏感或凭据 |
| 错误提示 | 用户可理解且可采取行动的提示 |

## 节点完成标准

一个节点只有同时满足以下条件才能标记为 `已确定`：

1. 用户目标、进入条件和完成条件没有歧义。
2. 主流程以及加载、空状态、失败状态都已覆盖。
3. 输入、输出和持久化字段已经定义。
4. 权限、隐私和源文件只读边界已经检查。
5. 验收场景可以直接转化为测试用例。
6. 相关决策已经回写主规划书。
