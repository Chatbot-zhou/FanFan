# 翻翻 V1 方案逐条审查清单

本清单以[翻翻 V1 产品与开发规划书](翻翻-V1-产品与开发规划书.md)3.2为需求源。只记录当前代码和本轮实际运行证据，不恢复用户旅程文件，不把旧安装包、历史测试或未完成的评测分数当成新版本证据。

状态定义：

- `已验证`：真实目标流程和必要故障路径已运行并有证据；
- `开发完成（待体验）`：代码链路存在且必要检查通过，但尚未由用户实际体验；
- `部分实现`：已有可执行基础，仍有计划内环节未完成；
- `未实现`：当前没有可用实现；
- `暂缓`：规划明确不在当前V1。

## 12. 用户体验重点

体验阶段重点观察：

1. 图标和字标是否与原图一致，标题栏、欢迎页和小图标是否清晰；
2. 问答或后台模型运行时，浏览器和其他应用是否仍流畅；
3. 麦克风是否只在点击后启用，语音文本是否先确认再发送；
4. 已验证回答能否朗读、暂停、继续和停止；
5. 多个模型任务是否保持紧凑稳定，暂停/继续/失败重试/切源/取消是否符合语义；重置后已安装模型是否完整；
6. PP-OCRv5下载、自检、图片/扫描PDF识别和“Paddle失败或低置信度 → Windows完成”是否真实；
7. 问资料是否真正经过混合检索和生成模型，引用失败时是否只显示错误而不展示摘录回答；
8. 多轮问答、Markdown、图片定位、集合、关系和收件箱是否可用；
9. 紧凑状态面板和日志是否能解释授权、索引、推理资源与错误。

出现问题时请保留日志并提供页面、操作顺序和大致时间。只有收到“验收通过，可以做最终测试”后，才执行完整回归、压力、真实模型矩阵、NSIS和安装烟测。
