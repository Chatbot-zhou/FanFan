# 翻翻真实资料全链路评测、故障修复与 RAG 优化计划

## 一、当前诊断与目标

当前真实数据基线：

- 两个授权位置共登记1506个文件，约2.71GB；新增目录实际枚举1649个文件。
- 新扫描前1500项成功写入，最后149项整批回滚，任务错误停留在`FILE_UPSERT_FAILED`和“扫描中”。
- 失败耗时1.747秒，与SQLite当前1.5秒锁等待高度吻合；未发现目录权限、路径冲突、硬链接或文件枚举错误。高概率是数据库写锁竞争，但现有日志丢失了底层SQLite错误，需补齐后最终确认。
- 1326个文件仍为`pending`，174个被标为`unsupported`，仅5个解析成功，1个PDF以`PDF_PARSE_FAILED`失败且没有保留具体原因。
- 现有776个Embedding和USearch键都来自旧资料；界面显示的“100%覆盖”只针对旧块，不代表新资料。
- 3次真实RAG均因`RAG_CITATION_VALIDATION_FAILED`失败；现有检索先按文件折叠，每个文件只取一个块，尚无真正的块级MMR。
- OCR和ASR虽登记为`ready`，但模型仓库分别缺检测/方向模型和Silero VAD；旧目录仍有这些文件，可校验恢复，无需重新下载。
- TTS、视觉模型和Rerank未安装。

最终目标是：修通当前2.71GB资料的扫描、识别、解析、OCR、切分、Embedding、USearch、搜索、严格RAG、关系、集合和语音链路，建立可重复评分体系，综合隐藏集得分达到85分以上，同时满足所有安全硬门禁。

## 二、P0故障修复与数据恢复

### 扫描和SQLite

- 用单一SQLite写入执行器替换分散连接写入，交互操作优先；WAL只在数据库初始化时配置，不再由每个连接重复执行。
- 扫描改为边枚举边分批提交，默认50项一批；锁竞争使用有限退避重试，确定性单文件错误用保存点隔离，不再回滚整个批次。
- 保留`scan_seen_memberships`检查点；恢复当前任务时重新枚举元数据，跳过已提交的1500项，只续写缺失149项。
- 每批提交后立即允许解析，不再等待整个扫描完全成功。
- 任何扫描异常必须原子更新任务、资料根和错误状态；启动时自动收口过期心跳，不再长期显示“扫描中”。
- 日志增加SQLite主错误码、扩展错误码、批次、重试次数和阶段，但不记录绝对路径。
- 对当前PDF重新执行一次带安全详情的诊断解析，区分损坏、加密、解析器缺陷或依赖问题；不可重试错误不再每次启动自动重复。

### 文件识别与处理状态

- 不再仅凭扩展名判断；组合扩展名、文件头、MIME、文本编码和容器结构分类。
- 将文件明确划分为：
  - 可解析正文；
  - 图片/OCR；
  - 只读代码或配置文本；
  - 归档清单；
  - 媒体元数据；
  - 安全元数据；
  - 加密/损坏/能力缺失；
  - 真正未知。
- `.text`、`.ini`、`.iml`及可安全识别的XML/文本类文件进入通用文本解析；EXE/DLL永不执行。
- RAR、数据库、视频和私有格式不再笼统显示“unsupported”，而显示明确的只读处理结果及未索引正文原因。

### 模型包完整性

- `ready`必须同时满足主文件、全部配套文件大小和SHA-256正确，并通过真实最小推理；仅主文件存在不得标记完成。
- 从旧目录复制并校验OCR检测/方向模型和ASR VAD文件；新仓库自检成功前保留旧副本。
- 下载并实测用户选择的轻量模型组：
  - Qwen3-VL 2B Q4及投影文件：约1.55GB；
  - BGE Reranker Base INT8：约296MB；
  - sherpa-onnx中文TTS：约121MB；
  - 合计约1.97GB。
- 不删除或覆盖现有Generation、Embedding、OCR、ASR及断点文件；测试前后对模型仓库做全量哈希比对。
- 本轮不自动升级当前Qwen3 0.6B生成模型；若它成为质量瓶颈，只报告1.7B/4B升级收益和资源成本。

## 三、检索、RAG及智能能力优化

### 可恢复索引链

- 解析按格式专用节点切分，保留文件修订、页码、段落、单元格、幻灯片、代码符号和图片坐标。
- 文本块继续以384/480/64为基础，但按标题、表格、代码函数和OCR行组避免机械截断。
- Embedding以`模型版本 + 修订 + 内容哈希`作为幂等键，小批次提交；失败只重试当前批次。
- USearch新代际后台构建，校验块数、维度、键映射和抽样近邻后原子切换，旧索引持续服务。
- 覆盖率改为分层展示：发现文件、可解析文件、已解析文件、FTS块、Embedding块、活动向量键、OCR/视觉待处理和明确排除项。不得再用“旧块全部有向量”冒充全库100%。

### 混合检索

- 抽出应用和评测器共用的

  ```
  HybridRetriever
  ```

  ，以块为检索单位：

  - SQL文件名/路径；
  - FTS5/BM25；
  - Embedding/USearch；
  - 加权RRF；
  - 修订与来源去重；
  - MMR多样性控制；
  - 可选Rerank。

- 普通找资料不再默认调用生成模型做查询理解；时间、类型等条件先用确定性解析，只有明确歧义才使用本地模型。

- 范围搜索使用USearch过取后过滤和递增补取，不再因为限定目录/集合而回退到全量SQLite精确向量扫描。

- 搜索结果最后才按文件折叠，同时保留最佳块、命中通道和真实通道状态。

### 严格多轮RAG

- RAG固定执行：历史追问改写 → 混合块召回 → RRF/MMR → 可选Rerank → 证据校验 → 生成 → 引文校验。
- 当前4K上下文默认选择最多10个块、6个文件和约2400 tokens证据；更大上下文模型可扩展至12块、8文件和6000 tokens。
- 生成输出改为受JSON Schema约束的`claims[] + citation_ids[]`，通过校验后再渲染Markdown，删除对自由Markdown句尾引用的脆弱解析。
- 每个事实检查引用存在、原文匹配、授权范围、当前修订和支持关系；引用不合格的内容不得显示。
- 无有效证据时明确拒答；Embedding、Generation或当前范围索引不可用时返回可操作错误，不返回检索摘录冒充答案。
- 多轮历史只用于理解追问，不作为事实来源；重启后恢复会话和失败重试状态。

### 关系、集合、OCR和语音

- 完全重复继续使用SHA-256；版本候选结合文件名、结构和内容变化。
- 语义关系使用文档Embedding和USearch近邻候选，模型只复核有限候选；测试同主题、同用途、包含、摘要和无关负例。
- AI集合以共同主题、类型和用途命名，评测成员纯度、覆盖率、逐成员理由、确认/拒绝和人工排除。
- 对真实图片分层执行PP-OCRv5、Windows OCR回退和低置信度VLM增强，并保存完整尝试链。
- ASR使用已知转写的中文及中英混合本地音频；VAD测试静音、噪声、停顿和端点。
- TTS测试生成、暂停、继续、停止、语速和禁止自动播放。
- 当前15个MP4只验证元数据和“需要显式启用转写”的交互；未经单独授权不读取其音轨内容。

## 四、本地评价体系与优化闭环

### 评测数据

- 使用SQLite在线备份创建一致性评测快照，保存在`%LOCALAPPDATA%\FanFan\Evaluation\v1`，加密并限制当前用户访问。
- 不把用户正文、提问、音频、数据库、路径或评测答案写入仓库、普通日志或网络。
- 数据集按文档家族划分60%调优、20%开发、20%隐藏测试，防止同一文件不同块跨集合泄漏。
- 用例组成：
  - 60条搜索：当前资料事实、同义改写、文件名、语义查询、范围过滤和负例；
  - 48个RAG回合：24个单轮、6组三级追问、6个无证据/越权问题；
  - 60对关系样本和12个集合主题簇；
  - 20张真实分层图片及20张有精确真值的OCR样本；
  - 20段ASR音频和10段TTS文本；
  - 固定损坏、加密、锁库、取消、断电恢复和模型缺失夹具。
- 本地模型可以生成问题改写和候选评分，但不能作为唯一裁判；事实、引用、权限、文件修订、OCR真值和确定性答案优先程序校验，并进行少量人工抽查。

### 百分制评分

- 扫描、解析和索引：20分；
- 搜索质量：20分；
- 严格RAG与多轮问答：30分；
- 资料关系和智能集合：10分；
- OCR、ASR和TTS：10分；
- Runtime、恢复、日志和性能：10分。

主要门槛：

- Search：Recall@10不低于0.90，MRR@10和nDCG@10不低于0.85，暖态混合检索P95不高于2秒。
- RAG：事实句引用覆盖率100%，越权引用拒绝率100%，无证据拒答正确率100%，事实正确性不低于0.85，P95不高于30秒。
- 关系：精确重复100%，语义关系Precision不低于0.85、Recall不低于0.80。
- OCR：受控集字符错误率不高于8%，真实抽样不高于15%，定位信息完整。
- ASR：清晰普通话CER不高于15%，中英混合不高于25%，静音不得产生幻觉文本。
- Runtime：取消2秒内生效；后台推理最多1–2线程；重模型互斥；搜索、预览和其他应用持续可用。

无论总分多少，以下任一项失败都不得通过：

- 源文件哈希发生变化；
- 读取未授权目录；
- 模型包不完整却显示可用；
- 扫描或索引任务永久停留在运行中；
- FTS、Embedding、USearch键映射不一致；
- 显示未经验证的生成内容；
- 日志包含正文、问题、音频或敏感绝对路径。

### 优化规则

- 先记录原始基线，再依次优化识别/切分、召回、融合/MMR、Rerank、证据预算、结构化生成和关系阈值。
- 每组参数最多三轮；只有开发集提升且隐藏集不下降、硬门禁继续通过时才接受。
- 保留文件名/FTS/Embedding/Rerank消融报告，明确每个模型是否真正产生收益。
- 综合隐藏集达到85分后停止调参；若未达到，输出按影响排序的瓶颈、失败样本类别和模型能力限制。
